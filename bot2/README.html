Guide d'installation
WhatsApp Bot

De zéro au déploiement en production — configuration, base de données, Whapi, cron et utilisation quotidienne.

1 Prérequis

Avant de commencer, vérifiez que votre serveur dispose de :

ComposantVersion minimumVérifier
PHP8.1+php -v
MySQL / MariaDB5.7+ / 10.3+mysql --version
Extension PDO MySQLactivéephp -m | grep pdo
Extension cURLactivéephp -m | grep curl
HTTPScertificat SSL valideWhapi exige HTTPS
Compte Whapiactif + numéro connectégate.whapi.cloud
⚠️

Whapi exige HTTPS. Votre webhook doit être accessible via une URL https://. Un certificat Let's Encrypt gratuit suffit. Sans SSL, Whapi refusera d'envoyer les événements.

2 Fichiers à déployer

Vous avez reçu 2 fichiers PHP et 1 fichier SQL. Structure attendue sur le serveur :

/var/www/html/
  ├── webhook.php     ← reçoit les messages Whapi
  ├── queue_worker.php ← envoie les messages en attente
  └── logs/
      └── webhook.log    ← créé automatiquement
💡

Le dossier logs/ doit être créable par le serveur web. Lancez : mkdir -p logs && chmod 775 logs depuis le dossier racine.

3 Base de données

Importez le schéma SQL. Toutes les tables sont créées avec IF NOT EXISTS — vous pouvez relancer l'import sans risque.

Créer la base et l'utilisateur

SQL — phpMyAdmin ou terminal
-- Se connecter en root
mysql -u root -p

-- Créer la base
CREATE DATABASE nufotec_db CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- Créer l'utilisateur
CREATE USER 'nufotec_user'@'localhost' IDENTIFIED BY 'MotDePasse_Fort_123!';

-- Donner les droits
GRANT ALL PRIVILEGES ON nufotec_db.* TO 'nufotec_user'@'localhost';
FLUSH PRIVILEGES;

Importer le schéma

Terminal
mysql -u nufotec_user -p nufotec_db < database.sql

Via phpMyAdmin : Sélectionner la base → onglet Importer → choisir database.sql → Exécuter.

✅

Après l'import, vous devez voir 11 tables : groupes_whatsapp, whatsapp_blacklist, whatsapp_inbox, whatsapp_logs, whatsapp_media, whatsapp_participants, whatsapp_queue, whatsapp_rate_limits, whatsapp_security_logs, whatsapp_settings, whatsapp_templates.

4 Configuration des fichiers PHP

Ouvrez webhook.php et queue_worker.php et modifiez les lignes en haut de chaque fichier :

PHP — webhook.php & queue_worker.php (début du fichier)
// ── Base de données ────────────────────────────
define('DB_HOST',  'localhost');
define('DB_USER',  'nufotec_user');      // ← votre utilisateur MySQL
define('DB_PASS',  'MotDePasse_Fort_123!'); // ← votre mot de passe MySQL
define('DB_NAME',  'nufotec_db');

// ── Whapi ───────────────────────────────────────
define('API_TOKEN',    'VghiTs88mPZt3GkeA7dGf4G6v3Av6Skw'); // votre token Whapi
define('API_URL',      'https://gate.whapi.cloud/');
define('MASTER_GROUP', '254743031262-1528423768@g.us');    // ID du groupe maître
define('WEBHOOK_TOKEN', '');  // laisser vide ou mettre un secret
⚠️

Changez ces valeurs dans les DEUX fichiers (webhook.php et queue_worker.php). Ils sont indépendants et chacun a sa propre section de configuration en haut.

Comment trouver l'ID du groupe maître ?

Envoyez n'importe quel message depuis le groupe WhatsApp vers votre webhook, puis regardez dans whatsapp_logs — la colonne phone_number pour les messages de groupes contient l'ID au format XXXXXXXXX-XXXXXXXXXX@g.us. Ou activez les logs DEBUG et cherchez chatId.

5 Configurer Whapi

1
Se connecter sur gate.whapi.cloud

Rendez-vous sur votre tableau de bord Whapi et sélectionnez le canal (channel) correspondant à votre numéro WhatsApp.

2
Copier votre token API

Dans Settings → API Token, copiez votre token et collez-le dans define('API_TOKEN', '...') dans les deux fichiers PHP.

3
Configurer le Webhook URL

Dans Settings → Webhooks, ajoutez l'URL de votre webhook :

URL webhook
https://votre-domaine.com/webhook.php
4
Activer les événements

Cochez au minimum ces événements dans Whapi :

  • message — messages entrants (obligatoire)
  • group_participants_update — ajout/retrait membres
  • message:status — statut de livraison (optionnel)
5
Tester la connexion

Cliquez sur "Test Webhook" dans Whapi. Votre serveur doit répondre 200 OK. Si vous obtenez timeout, vérifiez que l'URL est accessible publiquement.

6 Définir les administrateurs

Les admins peuvent envoyer des broadcasts depuis le groupe maître. Ils ne sont jamais soumis aux règles de sécurité.

Via phpMyAdmin

Dans la table whatsapp_settings, trouvez la ligne admin_numbers et éditez setting_value :

JSON — valeur de admin_numbers
// Un seul admin
["25779666439"]

// Plusieurs admins
["25779666439", "25761234567", "25778901234"]
💡

Les numéros sont au format international sans le + (indicatif pays + numéro). Burundi = 257XXXXXXXX. Les membres admins du groupe dans WhatsApp sont aussi reconnus automatiquement via la table whatsapp_participants.

Via SQL

SQL
UPDATE whatsapp_settings
SET setting_value = '["25779666439","25761234567"]'
WHERE setting_key = 'admin_numbers';

8 Worker & Cron

Le queue_worker.php lit la table whatsapp_queue et envoie les messages en attente. Il doit tourner régulièrement.

Méthode 1 — Cron (recommandé pour hébergements mutualisés)

Crontab — crontab -e
# Exécuter toutes les minutes
* * * * * php /var/www/html/queue_worker.php >> /dev/null 2>&1

# Ou avec chemin PHP explicite si nécessaire
* * * * * /usr/bin/php8.1 /var/www/html/queue_worker.php >> /dev/null 2>&1

Via cPanel : Aller dans Tâches Cron → Toutes les minutes → commande : php /home/VOTRE_USER/public_html/queue_worker.php

Méthode 2 — Mode daemon (VPS/dédié, diffusion instantanée)

Terminal SSH
# Lancer en arrière-plan
nohup php /var/www/html/queue_worker.php --daemon &

# Voir s'il tourne
ps aux | grep queue_worker

# L'arrêter
kill $(pgrep -f queue_worker.php)
💡

Le worker a un verrou automatique — si deux instances se lancent en même temps (ex. cron toutes les minutes + daemon), la deuxième s'arrête immédiatement sans erreur.

9 Tester le déploiement

1
Vérifier que le webhook répond
Terminal
curl -I https://votre-domaine.com/webhook.php
# Attendu: HTTP/2 200
2
Envoyer un message test via Whapi

Dans le tableau de bord Whapi → Test Webhook. Vérifiez ensuite logs/webhook.log — vous devez voir une ligne INFO Webhook reçu.

3
Tester la sécurité

Depuis un numéro non admin, envoyez un lien dans le groupe. Le bot doit :

  • Supprimer le message en moins de 2 secondes
  • Envoyer un message d'avertissement dans le groupe
  • Créer une ligne dans whatsapp_security_logs
4
Tester un broadcast

Depuis le groupe maître, envoyez : #groupe Bonjour à tous !

Vérifiez que des lignes apparaissent dans whatsapp_queue avec le statut pending. Après le passage du worker, elles passent à completed.

— Commandes admin

Toutes les commandes s'envoient uniquement depuis le groupe maître. Un message normal (sans commande) diffuse vers tout le monde.

#groupe Texte Diffuse uniquement vers les groupes listés dans groupes_whatsapp où actif=1
#inbox Texte Diffuse uniquement en messages privés vers les contacts dans whatsapp_inbox où is_blacklisted=0
#tous Texte Diffuse vers groupes + contacts privés (comportement par défaut sans commande)
#template:nom Utilise le contenu du template enregistré dans whatsapp_templates avec ce nom. Ex: #template:bienvenue
#template:promo Texte Template + texte supplémentaire ajouté après. Ex: #template:promo Valable jusqu'au 31 mai !
💡

Les médias (images, vidéos) envoyés depuis le groupe maître sont aussi broadcastés. Le texte de la légende est utilisé comme message texte si présent.

— Logs & Monitoring

Suivre les logs en temps réel

Terminal SSH
# Logs en direct
tail -f /var/www/html/logs/webhook.log

# Voir seulement les erreurs
grep "\[ERROR\]" /var/www/html/logs/webhook.log | tail -20

# Compter les violations aujourd'hui
grep "Violation" /var/www/html/logs/webhook.log | grep $(date +%Y-%m-%d) | wc -l

Surveiller la queue via SQL

SQL
-- État de la queue
SELECT status, COUNT(*) AS total
FROM whatsapp_queue
GROUP BY status;

-- Messages en attente
SELECT * FROM whatsapp_queue
WHERE status = 'pending'
ORDER BY created_at DESC LIMIT 10;

-- Violations récentes
SELECT sender, action_type, reason, created_at
FROM whatsapp_security_logs
ORDER BY created_at DESC LIMIT 20;

Mettre la queue en pause

SQL
-- Mettre en pause
UPDATE whatsapp_settings SET setting_value = '1' WHERE setting_key = 'queue_paused';

-- Reprendre
UPDATE whatsapp_settings SET setting_value = '0' WHERE setting_key = 'queue_paused';

Régler les délais d'envoi (anti-ban)

SQL
-- Délai minimum entre 2 envois (secondes)
UPDATE whatsapp_settings SET setting_value = '3'  WHERE setting_key = 'delay_min';

-- Délai maximum entre 2 envois (secondes)
UPDATE whatsapp_settings SET setting_value = '8'  WHERE setting_key = 'delay_max';

-- Nombre de tentatives avant échec définitif
UPDATE whatsapp_settings SET setting_value = '3'  WHERE setting_key = 'max_retries';

— Dépannage

ProblèmeCause probableSolution
Whapi renvoie timeout Webhook ne répond pas assez vite Le fichier répond en <1ms. Vérifier que l'URL est bien publique via curl -I https://...
Messages non supprimés Token API invalide ou expiré Vérifier API_TOKEN dans webhook.php, le comparer avec le tableau Whapi
DB connection failed dans les logs Mauvais identifiants MySQL Vérifier DB_USER, DB_PASS, DB_NAME et que l'utilisateur a les droits
Admin non reconnu Numéro mal formaté dans admin_numbers Format sans + et sans espace : ["25779666439"]
Queue reste en pending Worker ne tourne pas Vérifier le cron : crontab -l. Lancer manuellement : php queue_worker.php
Webhook reçoit mais n'agit pas MASTER_GROUP incorrect Vérifier l'ID dans les logs (chatId) et le comparer à la constante
Logs vides Dossier logs/ sans permission chmod 775 logs/ && chown www-data:www-data logs/
Erreur 500 Extension PDO ou cURL manquante php -m | grep -E "pdo|curl" — installer si absent

Activer les logs DEBUG

Dans webhook.php, dans la fonction wlog(), changez le niveau minimum :

PHP
// Ligne à trouver dans la fonction wlog()
if (($levels[$level] ?? 1) < 0) return;  // ← mettre 0 pour voir DEBUG
// (valeur normale = 1 pour INFO et au-dessus)
